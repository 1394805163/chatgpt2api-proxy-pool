# ChatGPT2API v1.8.3 Stability Plan

> Release planning document only. This branch does not contain the 1.8.3 code
> implementation yet. Local execution must start from this branch and must use
> temporary configuration/data directories, never production data.
>
> Search marker: `v1.8.3-stability`.

## Goal and workflow

The release is GitHub-first:

```text
GitHub branch -> local clone -> unit tests -> mocked upstream SSE tests
-> Docker smoke test -> manual production deployment only after acceptance
```

Baseline: GitHub `origin/lite` commit `7d9e1e4` (`1.8.2`). Do not merge the
old VPS snapshot wholesale; it diverged across the image request paths.

Planned branch and release:

```text
branch: codex/v1.8.3-stability
version: 1.8.3
tag: v1.8.3 (only after local acceptance)
```

## Production evidence

The following evidence was collected read-only before this plan was published:

- After the 2026-08-23 restart, the app recorded 92 `image_stream_fail`
  curl timeouts and 89 retries. The sampled timeout messages had non-zero
  received bytes, so they were partial SSE timeouts rather than clean connect
  failures.
- In the Beijing-time 23:00 window, key `悠米` had 75 image calls, 36
  successes and 39 failures, with an average duration around 233 seconds.
  The earlier 22:00 window was mostly 40-60 seconds.
- The running `v1.8.2` container used the old unconditional curl-timeout
  retry path. Host source and the running container were different because
  `services/` and `api/` are not mounted into the container.
- The observed issue is request/retry accumulation. It is not a new OOM:
  the post-restart container remained healthy with no cgroup OOM kill.

## Required behavior

### Preserve 1.8.2

- Multi-image billing and cumulative counts use the actual successful image
  count; failed images are not charged.
- `n` consumes the requested number of concurrency and daily-quota units.
- Responses image requests pass through `n` and reject unsupported combinations.
- A timed-out worker keeps its physical lease until it exits; no bypass worker
  is created.
- Existing global, user, account, and per-request limits do not change.
- Existing account, key, image, task, and SQLite data remain compatible.

### Fix 1.8.3 image timeout behavior

- Disable curl low-speed timeout for image SSE; the unified task deadline owns
  the stream lifetime.
- If SSE has yielded any bytes or a `conversation_id`, never submit a second
  generation. Continue polling the original conversation.
- Only a connection-establishment timeout with zero received bytes may retry,
  and it may retry at most once.
- Polling deadline returns one `504 image_task_timeout` result or uses the
  existing async resume flow; it never switches account to regenerate.
- Content-policy refusals remain `400 content_policy_violation` and are never
  retried.

### Memory and WebUI stability

- Close SSE, upload, and download responses on all success and failure paths.
- Release worker references and leases only after the worker exits.
- Remove orphaned image input spools.
- Keep API response fields compatible; offload heavy account/log reads from the
  FastAPI event loop and keep log pages bounded.
- Do not store image bytes or Base64 in Redis. Redis business integration is
  outside 1.8.3; the independent Redis container remains infrastructure only.

## Code and test execution map

| Requirement | Planned code location | Planned test location |
| --- | --- | --- |
| SSE low-speed handling | `services/openai_backend_api.py:_start_image_generation` | `test/test_multi_image_results.py` |
| Received-byte parsing and retry gate | `services/protocol/conversation.py:is_pre_request_connection_timeout_error` and `_generate_single_image` | `test/test_multi_image_results.py` |
| Partial SSE resume | `services/protocol/conversation.py:stream_image_outputs` | `test/test_multi_image_results.py` |
| Poll timeout without resubmit | `services/protocol/conversation.py:_generate_single_image` | `test/test_multi_image_results.py` |
| 1.8.2 accounting/concurrency | `api/ai.py`, `services/image_concurrency.py`, `services/image_task_service.py` | existing quota/concurrency suites |
| Response and worker cleanup | `services/openai_backend_api.py`, `services/image_task_service.py` | `test/test_backend_session_lifecycle.py`, `test/test_image_task_service.py` |

Implementation comments must use `v1.8.3-stability`; new regression tests must
use the `test_v183_` prefix. This prevents local AI tools from confusing the
1.8.2 baseline, the old VPS snapshot, and the 1.8.3 changes.

## Local test cases

The local implementation must add or update these cases:

1. Partial SSE timeout with bytes received: one upstream POST, then poll the
   original conversation.
2. Zero-byte connection timeout: at most one retry, then a timeout error.
3. Poll timeout: one `504`, no account switch and no second generation.
4. Content-policy refusal: `400`, zero retries.
5. `n=3` with two successful images: charge two, not three.
6. Error paths close SSE, upload, and download responses.
7. Worker and lease state returns to idle after timeout.

## Acceptance commands

Run from the local clone with temporary test configuration/data:

```bash
uv run pytest \
  test/test_image_concurrency.py \
  test/test_image_task_service.py \
  test/test_image_task_quota.py \
  test/test_api_request_quota.py \
  test/test_multi_image_results.py \
  test/test_v1_images_generations.py \
  test/test_v1_images_edits_api.py \
  test/test_v1_responses.py
uv run pytest
```

Build the local verification image without production data:

```bash
docker build --build-arg BUILDPLATFORM=linux/amd64 \
  --build-arg TARGETPLATFORM=linux/amd64 \
  --build-arg TARGETARCH=amd64 \
  --target test -t chatgpt2api:v1.8.3-test .
docker run --rm chatgpt2api:v1.8.3-test
docker build --build-arg BUILDPLATFORM=linux/amd64 \
  --build-arg TARGETPLATFORM=linux/amd64 \
  --build-arg TARGETARCH=amd64 \
  --target app -t chatgpt2api:v1.8.3-local .
```

Smoke acceptance must verify `/app/VERSION` is `1.8.3`, the container contains
the `v1.8.3-stability` markers, `/health?format=json` returns `200`, and image
success, policy refusal, and timeout responses preserve their API shapes.

## GitHub delivery and rollback

This planning commit must not include `.env`, production `config.json`,
`data/`, `backups/`, `redis_data/`, or production logs. The code implementation
comes in later commits on this same branch. Only after local focused tests,
full tests, and Docker smoke pass should `v1.8.3` be tagged and an image
published.

Keep the `1.8.2` image reference and backups until acceptance is complete. On
failure, switch the local/deployment image back to `1.8.2`; never delete the
data directories as part of rollback.
